阶段：设计。以下复选项为最终业务项目的提交门禁；当前业务程序未实现，不勾选未发生的工作。

## 2. 仓库内容

- [ ] README 含环境、安装、运行、评审入口和限制。
- [ ] src/ 有实际可运行程序，不只有接口或伪代码。
- [ ] tests/ 有可执行测试，且保存实际结果。
- [ ] examples/ 至少三组实际输入、输出和运行记录，并覆盖六项验收。
- [ ] data/ 有合成素材、规则、排期和版本说明。
- [ ] docs/01～05 齐全，与最终实现一致。
- [ ] 依赖精确锁定，并从干净环境验证。
- [ ] .env.example 说明配置，未包含真实值。
- [ ] CLI 对模型缺失、工具错误和上限有明确状态。

当前目录只有文档和配置说明，不能据此勾选源代码、测试和运行证据。

## 3. 关键质量门禁

- [ ] 没有真实发布工具或“已发布”成功状态。
- [ ] 原要求、建议时间、确认与保存分开记录。
- [ ] pending不占位；确认绑定具体草稿版本与时间。
- [ ] 时间变更、旧确认、新冲突都有实际测试。
- [ ] 重复请求跨进程不产生重复草稿；同键改参数被拒绝。
- [ ] 保存前再次检查；失败不报成功。
- [ ] 保存 unknown 有明确边界；如未实现恢复，列出限制。
- [ ] Trace 的动作确实来自本次模型输出，无人工预写决策路径。
- [ ] Mock/FakeModel/live 分别标记，失败试次没有删除。
- [ ] 项目声明的能力均有代码或证据支撑。

## 4. 安全、保密与评审访问

- [ ] 不上传真实密钥、Header、Token、手机号、私人账号或真实素材。
- [ ] 不上传原始试卷、考核页面、截图或完整题面。
- [ ] 项目文档只表述自己的需求、设计、代码和验证结果。
- [ ] 在题目保密范围未另获许可时，默认私有仓库并赋予指定评审账号只读访问。
- [ ] 评审账号以考核通知为准；未收到账号时不自行编造。
- [ ] 访问权限可读不等于仓库公开；不要为了演示擅自公开考题材料。

用户提供的规则同时要求 GitHub 提交并限制试题传播；本项目采用最小披露。公开技术资料查询没有附带完整试题内容。

## 5. 最终提交动作

- [ ] 业务代码、文档和脱敏证据均纳入同一仓库。
- [ ] 全部必需测试完成；未完成与失败如实写入评估。
- [ ] 本地提交已推送，GitHub 上可查看对应提交。
- [ ] 生成证据的 source_commit 与最终代码一致，证据追加提交没有修改业务逻辑。
- [ ] git status --short 无意外遗漏；不要求忽略的运行数据库入库。
- [ ] git rev-parse HEAD 返回最终40位SHA，远端存在该提交。
- [ ] 指定评审账号可读，且无需使用候选人本机环境。
- [ ] 提交题号1、GitHub URL、最终SHA；文字说明指向 README。

最终提交文本格式（不是现有远端信息）：

~~~text
题号：1
项目：素材审核与发布排期 Agent
GitHub URL：实际仓库地址
最终 commit SHA：实际40位提交值
评审入口：README.md
验证：离线实际结果；live实际结果；未完成项
~~~
